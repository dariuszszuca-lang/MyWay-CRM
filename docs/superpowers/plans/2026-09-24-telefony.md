# Telefony: plan implementacji

Zatwierdzony kierunek: prosty układ A, dopasowany do obecnego CRM (Darek: „Tak żeby było czytelnie i prosto, dopasuj”). Wykonanie lokalnie, bez subagentów.

Cel: dziennik rozmów i kontaktów, analiza, PDF/CSV oraz archiwalne raporty okresowe.
Architektura: izolowany moduł React ładowany na żądanie; osobne kolekcje Firestore phoneContacts, phoneCalls, phoneFinancials, phoneReports, phoneAudit. Wspólne czyste obliczenia ES module dla przeglądarki i harmonogramu Firebase.

- [x] Testy `tests/telephony.test.mjs`: kalendarz PL, granice okresów, rozdzielenie kontaktów/prób/wygranych, brak danych, walidacja, eksport CSV.
- [x] `functions/telephony/core.mjs`: czyste obliczenia; `services/telephony.ts` i `services/phoneStore.ts`: typy i atomowy zapis z kontrolą rewizji; kwoty wyłącznie w kolekcji finansowej.
- [x] `components/TelefonyTab.tsx` + `components/telephony/*`: wpis, lista, karta kontaktu, analiza i raporty. Pola szczegółowe rozwijane. Filtry oraz stany ładowania/błędu/pustej listy.
- [x] `services/telephonyExport.ts`: PDF z lokalnymi fontami i CSV z ochroną formuł.
- [x] `functions/telephony/scheduler.cjs`: idempotentne raporty tygodnia/miesiąca/roku, agregaty bez PII, dzienne sprawdzanie brakującego raportu. `functions/telephony/index.cjs`: osobny codebase i konto serwisowe.
- [x] `firestore.rules`: nowe kolekcje bez zmiany istniejących uprawnień; finanse i raporty tylko dotychczasowi odbiorcy statystyk. Testy emulatorem.
- [x] `App.tsx`: osobny rząd menu i lazy loading modułu. Desktop/tablet/telefon i regresja pozostałych kart.
- [x] `tools/preview-phone-import.py`: podgląd historycznych danych bez zapisów do produkcji.
- [x] `npm test`, `npm run build`, kontrola przeglądarką na syntetycznych danych, przegląd diff, commit. Przygotowanie zakresu wdrożenia backendu do zgody przed publikacją zależnego interfejsu.

Nie importować historii do produkcji bez zaakceptowanego podglądu. Nie wdrażać nowych reguł/funkcji GCP bez zgody. AI_ACT_CHECK: NIE_DOTYCZY, raporty deterministyczne.
